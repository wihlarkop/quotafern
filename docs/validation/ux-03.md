# UX-03 — Accounts simplification and UI polish

Implemented on `codex/ux-03-accounts-polish`, from merged PR #16 baseline `da1094aba9c4459ac15a9b5ab6deff3557045042`. Verification completed 2026-10-29 (Asia/Jakarta). This milestone has no real authenticated or native GUI acceptance claim.

## Result and rationale

- Ordinary accounts show their name, provider, reported plan when present, lifecycle and one contextual menu. Connection names, verified identities and diagnostics remain available through disclosure. Missing identities/plans are omitted. Multiple connections and workspace selection retain stable ID-based routing; collapsed connections retain visible failure warnings.
- Add account offers the available provider, existing Codex login or another account, and an optional sensible name. Continue closes the management dialog before requesting the existing native Connect/login flow. Cancel does not request native access. Saved labels do not grant permission.
- Rename, Refresh, Disconnect, Reconnect, Sign in again and Remove remain contextual. Removal still awaits native cleanup; failed cleanup keeps the account and other accounts remain independent. The existing controller's one-active-connection-per-account guard is preserved.
- Consent leads with quota access, remembered reconnection and Disconnect revocation. The existing-login helper disclosure stays visible. Complete native disclosure strings remain under connection/authentication details. Native challenge validation, IPC capabilities, policy version, isolated entry/window, grants and adapter behavior are untouched.
- Overview prioritizes remaining quota and reset times. Reported zero remains zero, missing fields remain absent, shared quota appears once, and unknown billing-association warnings remain visible. Failure notices remain visible alongside successful accounts. Duration copy is human-readable. Accounts uses the app clock, synchronized when a native presentation arrives, so a newly received reading is not prematurely labeled stale.
