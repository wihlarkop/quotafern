Measure and reduce avoidable build work while preserving UX-03, security, accessibility and the Bun-only/Oxc-first stack. ## Evidence and selected approach

The baseline workflow runs eight Svelte checks and seven Vite builds. Desktop Clippy needs generated frontend assets, but Tauri later repeats the same frontend build. The consent entry imports two icons through the Lucide barrel, causing 2,140 Svelte compile transforms in local build logs.

The selected approach is limited to measured, low-risk pipeline deduplication and direct icon imports, as authorized by the owner. Preserve checked local `build` and Tauri's normal `beforeBuildCommand`. Add an asset-only package script; CI runs Svelte diagnostics once in its frontend quality job, produces assets once per job, and uses an explicit CI-only Tauri override to skip the duplicate frontend hook after assets already exist. Every native quality gate remains in the three-OS matrix. Change the two consent icon imports to the same individual-entry style already used by the main app. The composition audit also found the full variants library inlines another merge engine: use its supported lite entry for custom Button variant tokens, retaining the existing final utility merge, only after class-equivalence and size checks.

Alternatives considered: dependency replacements/feature trimming have no demonstrated safe win and risk class merging, TLS, tray or process behavior; runtime clock/projection restructuring has no demonstrated user-visible bottleneck and could alter freshness, cancellation or polling. Defer both. Investigate Cargo caching and release profiles without adopting unmeasured changes.

## Invariants

No UI design changes; no new framework, package manager, component library or standalone unit suite. No TDD. Do not alter Rust provider code, CSP, permissions, adapters, identity checks, consent, remembered authorization, telemetry policy, cooldown, three-minute refresh, Windows live availability or retired gates. Do not access real credentials or launch an app that might resume owner grants. Use synthetic browser fixtures and native regressions. Never clean the primary Cargo target. Never merge, tag or release.

## Verification and limits

Record all timing samples, environment, cache state, exact source SHA and raw/gzip/Brotli asset sizes. Compare alternated warm frontend builds under the same command/cache conditions; separate first-run samples. Capture bundle composition with a scratch Vite plugin, clearly distinguishing pre-minification module contributions from shipped sizes. Measure native debug/release first-target versus incremental builds with two jobs in an isolated target. Validate the CI override with actual Tauri compilation and exact-commit Linux/Windows/macOS hosted CI.

Run existing frontend/native quality scripts and source/production browser QA with fixture-only IPC. Compare produced assets and interactions; do not claim a size or runtime improvement when only build work was reduced. Authenticated monitoring, native OS focus/tray, startup and idle consumption remain owner acceptance where no safe isolated method has been exercised. Independent GPT-6 Luna High reviews measurements, portability, runtime/security boundaries and final diff; fix actionable P0-P2 findings.
