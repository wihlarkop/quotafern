# CODEX-LIVE-01 Implementation Plan

**Goal:** Personal multi-account Codex server quota inside the existing ACC-04 UI.
**Architecture:** A separate native direct-HTTP adapter reads only a consented Codex profile and requests one fixed HTTPS usage endpoint. ACC-04 remains the metadata authority; an ephemeral renderer projection maps sanitized, account-bound results into its existing source cards. The old app-server gates remain closed.
**Tech stack:** Bun 1.4.4, Svelte 5, Tauri 2, Rust, Oxc; no TDD.
**Spec:** Owner CODEX-LIVE-01 request supplied 2026-10-26.

## Constraints and decisions

- No UI redesign, generic auth platform, app-server quota polling, session-log fallback, custom OAuth, billing or inference.
- Native reads selected file auth only after consent; unsupported keyring-only auth offers managed login. Codex owns login and credential renewal.
- Managed homes use stable opaque ACC account IDs, never aliases or renderer paths. Removing metadata disconnects but does not delete credentials.
- Both direct production gates stay false pending dedicated review and owner native/real-account acceptance. No real developer or CI credentials are read.
- Fixed main-window commands accept opaque account/connection IDs and system/managed enum only. Tokens and native identities never cross IPC.
- Request cancellation and generation invalidation apply per account. Redirects disabled; TLS, deadlines and body bounds enforced; errors are static diagnostics.
- Preserve F1/other-provider/CSP/release safeguards. Only non-sensitive metadata and existing appearance preferences persist in renderer storage.
