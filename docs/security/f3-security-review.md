# F3 security review

Review snapshot: F3 commits through `ac05182` plus the current uncommitted security-gate working tree, checked 2026-10-24. This is a static source/configuration review. I did not run builds or tests; the lead agent runs Rust regression separately. No real Codex process, account, credential file, keychain, or authenticated request was used.

## Findings

No actionable code finding remains in this static pass after rechecking the latest working tree. In particular, `refresh_locked` checks the terminal `stopping` flag ([`codex.rs:721-723`](../../src-tauri/src/codex.rs#L721)); shutdown sets it before disconnect ([`codex.rs:788-790`](../../src-tauri/src/codex.rs#L788)); and disconnect retains the session mutex through worker shutdown and final snapshot clearing ([`codex.rs:769-783`](../../src-tauri/src/codex.rs#L769)). This prevents a concurrent refresh after shutdown and prevents an older disconnect from clearing a newer connection's snapshot.

## Live-enablement and platform blockers

- **Startup policy remains the controlling blocker.** `LIVE_CONNECTION_ENABLED` is false ([`codex.rs:42`](../../src-tauri/src/codex.rs#L42)) and the renderer availability constant is false ([`codex.ts:94`](../../src/lib/codex.ts#L94)). The native command returns before PATH discovery, version probing, process creation, or RPC ([`codex.rs:608-616`](../../src-tauri/src/codex.rs#L608)). The pinned Codex 0.164.0 source investigation documents possible persisted Remote Control restoration, cloud-config refresh, model refresh, and Codex-owned auth refresh/state writes without a supported quota-only startup switch ([startup investigation](f3-startup-security-investigation.md)). Do not lift the gate based on protocol tests or owner account access.
- **Consent cancellation is statically improved, but not an OS acceptance claim.** The in-memory consent token is not serializable; Disconnect revokes it before waiting on the shared spawn/write barrier ([`consent.rs:27-37`](../../src-tauri/src/codex/consent.rs#L27)). New spawn ([`codex.rs:877-886`](../../src-tauri/src/codex.rs#L877)) and outbound-frame operations ([`codex.rs:369-384`](../../src-tauri/src/codex.rs#L369)) check the revoked flag while holding that barrier, while the I/O watchdog can terminate a child during a blocked write ([`watchdog.rs:16-43`](../../src-tauri/src/codex/watchdog.rs#L16)). Source and synthetic tests cover denied/late approval, in-flight barrier ordering, and no post-revocation spawn/write ([`consent.rs:97-135`](../../src-tauri/src/codex/consent.rs#L97), [`lifecycle_tests.rs:61-94`](../../src-tauri/src/codex/lifecycle_tests.rs#L61)). This is static/test-source evidence only; actual native dialog behavior is still unverified. The production dialog is behind `cfg(not(test))`; the test presenter is not wired as a production approval mechanism ([`codex.rs:1471-1485`](../../src-tauri/src/codex.rs#L1471)).
- **Unix forced termination is not covered by process groups.** Linux/macOS process groups are created and terminated on graceful cleanup ([`process_unix.rs:37-54`](../../src-tauri/src/codex/process_unix.rs#L37), [`process_unix.rs:72-87`](../../src-tauri/src/codex/process_unix.rs#L72)). A hard kill or forced OS termination skips Rust cleanup; Unix does not automatically kill a process group when its leader exits, so a Codex child may survive Quotafern. Windows has a kill-on-close Job Object ([`process.rs:441-461`](../../src-tauri/src/codex/process.rs#L441)); the lead records normal fake-process runtime separately, while forced application-termination acceptance remains unverified. Keep forced-termination behavior as a live-enablement/release blocker or document the accepted platform limit explicitly.
- **Native cross-platform acceptance remains pending.** The fixed command allowlist, mock process tests, and platform compilation do not prove OS dialog interaction, descendant cleanup, or reader shutdown on Windows/macOS/Linux. Continue to report these as NOT RUN until owner/platform acceptance is recorded.

## Reviewed controls

- Tauri exposes only fixed, argument-free lifecycle commands. `capabilities/main.json` scopes the four Codex permissions to `main`; each command also checks the window label. No remote capability is configured, and the release CSP is unchanged. Tauri's capability model defaults to bundled content; remote origins require an explicit `remote.urls` entry ([official capabilities documentation](https://v2.tauri.app/security/capabilities/)).
- Outbound RPC is restricted to `initialize`, `account/read`, `account/rateLimits/read`, `account/usage/read`, plus the fixed `initialized` notification. Account reads set `refreshToken: false`; raw error text, auth fields, account identity, provider IDs, and arbitrary labels do not cross IPC.
- JSONL frames are bounded to 1 MiB with an eight-frame synchronous queue; response IDs, result shape, and protocol headers are checked. Presentation DTOs use generated labels, static diagnostics, validated timestamps/counts/decimals, bounded bucket/reset/day counts, and account-generation invalidation. Disconnect clears the in-memory snapshot; no connection or usage state is persisted.
- Demo and live sources remain distinct. The frontend and Rust production gates are false, and failed live paths do not invoke synthetic demo factories.
- The native dialog dependency is pinned to `tauri-plugin-dialog = 2.8.3`; its locked transitive set includes `rfd`, `tauri-plugin-fs` support types, and additional Windows bindings. The filesystem plugin is not initialized and no dialog/filesystem capability is granted to the renderer. No frontend dependency or provider HTTP client was added. This was a manifest/lockfile review, not a vulnerability-database audit.
- The `native-regression` Cargo feature is empty at the Rust dependency level and is used by `regression:rust`; its `build.rs` common-controls manifest arguments are conditional on Windows plus that feature. The test presenter/plugin substitution is compiled under `cfg(test)` while the native OS presenter and dialog plugin are production-only. This source review did not compile either configuration.
- The startup investigation explicitly leaves authenticated acceptance, executable provenance, and native platform behavior unverified. The documented malicious/replaced local executable and compromised-OS assumptions remain outside the trust boundary.

## Review conclusion

The closed production gate contains the unfinished Codex startup policy and credential/side-effect uncertainty. The reviewed command/RPC/DTO and protocol boundaries are narrowly scoped, and the latest source closes the previously noted shutdown-refresh race. Keep live connection disabled until the documented startup policy is resolved and owner-driven native/platform acceptance covers process cleanup. Unix forced termination remains a specific blocker: process-group cleanup works during graceful shutdown, but a forced parent kill can leave descendants running because Rust cleanup cannot execute.
